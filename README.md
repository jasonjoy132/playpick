# 플레이픽 (PlayPick) · 맞춤형 게임 큐레이션 웹사이트

함께할 **인원수 · 플랫폼 · 장르**를 고르면 조건에 맞는 게임을 추천 목록으로 보여 주고,
게임 상세 정보 확인 후 외부 구매처로 이동할 수 있는 웹사이트입니다.
(디지털미디어학과 202322155 김준영 · 원페이저/발표 대본 기준으로 구현)

> ⚠️ **기본값은 데모 데이터입니다.** 게임물관리위원회 API는 공식 가이드 기준으로 연동 코드를 작성했고
> `DATA_SOURCE=live` 로 켤 수 있지만, **실제 서버 응답으로는 아직 검증하지 못했습니다**(가이드 샘플 응답으로만 테스트).
> **live 모드의 기본 출처는 IGDB**이고(Twitch Client ID/Secret 필요), 게임물관리위원회 API는 IGDB에 없는 게임 추가와 국내 등급분류 정보 보완에 씁니다.
> (원페이저는 ‘게임물관리위원회 API + 국내 게임 DB API’ 기준이었으나, 개발 중 IGDB 기반으로 변경했습니다.) 국내 게임 DB API는 서비스가 정해지지 않아 연결되어 있지 않습니다.
> 실제 호출 점검: `npm run check:apis` → `api-check.log`

## 1. 주요 기능 / 화면

### 상단 메뉴
| 메뉴 | 경로 | 내용 (IGDB 기준) |
|---|---|---|
| 홈 | `/` | 캐러셀·나만의 게임 찾기·로그인 창·인기 게임 한 줄(‘더 보기 →’는 인기 게임으로) |
| 인기 게임 | `/popular?platform=` | IGDB 평가 수(`total_rating_count`) 많은 순, 플랫폼 필터, 24개씩 더 보기 |
| 신작·출시 예정 | `/new?tab=recent\|upcoming` | 최근 출시: 최근 90일 출시작 중 출시 전 관심(`hypes`) 많은 순 / 출시 예정: 첫 출시일이 미래인 게임, 관심 많은 순(개발 취소 제외). 카드에 출시일 표시. 출시일은 IGDB 첫 출시일 기준이라 국내와 다를 수 있음 |
| 평점 랭킹 | `/ranking?tab=global\|members` | 글로벌 평점 TOP: IGDB 종합 평점 높은 순(평가 100개 이상만) / 회원 평점 TOP: 플레이픽 회원 평균 별점 높은 순(같으면 평가 많은 순, 최대 50개) |
| 장르별 게임 | `/genres/:genre?platform=` | 10개 장르 중 선택 → 그 장르의 인기 게임, 플랫폼 필터 |

데모 모드에서는 인기·장르별은 데모 게임으로, 신작·글로벌 랭킹은 데이터가 없어 안내 문구를 보여 줍니다.

| 화면 (경로) | 내용 |
|---|---|
| 첫 화면 (`/`) | 대표 게임 캐러셀(5개, 5초마다 넘김·마우스를 올리면 멈춤), 인기 게임 목록, ‘여럿이 함께하기 좋은 게임’(최대 3명 이상) |
| 조건 설정 창 | 상단·첫 화면의 **‘나만의 게임 찾기’** 버튼 → 인원(상관없음/1/2/3/4/5명 이상)·플랫폼·장르 선택 → 추천 목록으로 이동. Esc·바깥 클릭으로 닫힘 |
| 추천 목록 (`/results?players=2&platforms=pc&genres=rpg`) | ‘모든 조건 일치’ / ‘일부 조건 일치’ 구분, 카드마다 ✓일치·✕불일치·?정보 없음, 24개씩 더 보기, ‘조건 변경’은 기존 조건이 채워진 창 |
| 게임명 검색 (`/search?q=`) | 상단 검색창. live: IGDB 검색 + 게임위 게임물명 검색(IGDB에 없는 게임만 추가) |
| 게임 상세 (`/games/:id`) | 표지·배너, **한국어로 번역한 소개(원문 보기 가능)**, 인원·플랫폼·장르·국내 등급, 내 조건과 비교, 구매처 |
| 구매처 이동 | 새 창으로 외부 스토어. 데모 데이터는 앱 내부 ‘데모 구매처’ 안내 페이지(`/demo-store/:id`)로만 이동 |

상태 화면: 불러오는 중, 결과 없음, 데이터/API 오류(다시 시도), 일부 출처 실패 경고, 게임 없음(404).
반응형: 데스크톱 / 태블릿 / 모바일(390px).
디자인: 밝은 회청색 배경, 표지 중심 카드, 큰 캐러셀(사용자 시안 기준). 표지가 없는 게임은 그림을 만들지 않고 ‘이미지 없음’ 자리표시로 표시합니다.

넣지 않은 것: AI·개인화 추천, 관리자 화면(리뷰 신고·관리 포함).
원페이저의 성과 지표(클릭률·구매처 이동률·만족도·재방문율) **측정 기능은 아직 구현하지 않았습니다.**

### 게임 제보 (회원) → 관리자 승인
- **제보**(로그인한 회원만, `/submit`, 사용자 메뉴·검색 결과 아래 ‘게임 제보하기’): 게임 이름(필수), 영문 이름, 플랫폼·장르(필수, 사이트 분류에서 선택), 추천 인원, 구매처 링크, 개발·유통사, 출시 연도, 소개(1000자), 표지 이미지.
  - 이름을 입력하면 이미 있는 게임일 수 있는 목록을 보여 줍니다(검색 API 재사용).
  - 구매처는 **공식 스토어 주소만**(Steam·App Store·Google Play·닌텐도·PlayStation·Xbox·Epic·GOG·itch.io, 기존 `storeFromUrl` 허용 목록). 표지는 브라우저에서 긴 쪽 800px로 줄여 보내고, 서버가 파일 앞부분으로 PNG·JPG·WebP인지 확인(최대 1.5MB) 후 `.data/submission-images/` 에 저장.
  - 한 사람이 ‘검토 중’ 10개까지, 같은 이름 중복 제보 불가, 검토 중일 때만 취소 가능.
- **관리자**: `.env` 의 `ADMIN_EMAILS`(쉼표 구분, 대소문자 무시)에 적힌 이메일로 가입한 계정. 서버가 매 요청마다 확인하므로 화면을 조작해도 권한이 생기지 않습니다(`/api/admin/*` 는 비관리자 403).
  - `/admin`: 검토 중 / 승인됨 / 거절됨 탭, 제보 내용·제보자·표지, ‘같은 이름이 이미 있는지 검색’, **승인(게임 추가)**, **거절(사유 필수)**, 승인된 게임 **내리기**(사유 필수).
- **승인되면** id `user-<번호>` 게임으로 추가: 검색(이름·영문 이름에 검색어 포함 시 맨 앞), 나만의 게임 찾기(첫 요청에서 조건 판정 후 해당 섹션에), 상세 페이지(출처 ‘사용자 제보 (닉네임님) · 관리자 확인’, 추천 인원 출처 ‘사용자 제보’), 찜·리뷰 모두 동작. 카드에는 ‘제보’ 표시.
- **명예 뱃지·칭호** (`server/community/badges.js`): 따로 저장하지 않고 **승인된 제보**와 그 게임의 찜·리뷰 수로 그때그때 계산(관리자가 내리면 자동으로 다시 계산). 회원이 고른 대표 칭호만 `users.title_badge` 에 저장, 고르지 않았거나 자격이 없어지면 가장 높은 단계 칭호를 자동 표시.
  - 단계 칭호(승인 수): 🔍 첫 발견자 1 · ⛏️ 게임 발굴단 3 · 🏹 정보 사냥꾼 10 · 🧭 숨은 게임 탐험가 30 · 👑 플레이픽 큐레이터 50 (단계가 오를수록 색이 화려해지고 큐레이터는 반짝임)
  - 리뷰 칭호(리뷰를 남긴 게임 수, 게임마다 1개라 같은 게임으로 못 늘림): ✍️ 새내기 리뷰어 1 · 💬 한줄 평론가 5 · 🎙️ 게임 리뷰어 20 · 📰 베테랑 평론가 50 · 🏆 전설의 평론가 100
  - 자동 칭호는 제보·리뷰 단계 중 더 높은 것(같으면 제보). 리뷰를 쓰거나 지우면 바로 다시 계산.
  - 특별 뱃지: 📖 정성 리뷰어(100자 넘는 리뷰 10개) · 🌟 길잡이(아무도 리뷰 안 한 게임에 첫 리뷰 3번) · 🚩 개척자(제보 게임에 다른 회원 리뷰) · 💖 인기 발굴가(제보 게임 찜 합계 20, 본인 제외) · 📝 꼼꼼한 기록가(표지·구매처·소개·추천 인원 모두 채운 승인 5) · 🇰🇷 국내 게임 지킴이(모바일·아케이드 승인 5) · 🌱 얼리 어답터(2026년 안 첫 승인)
  - 뱃지 그림: `client/public/badge-<id>.webp` (128px, 디자인 시안 한 장을 잘라 만듦). 그림을 못 불러오면 이모지로 대신 표시.
  - 표시: **닉네임 앞에 뱃지 그림만**(칭호 이름은 마우스를 올리면 툴팁) — 리뷰, 사용자 메뉴, 마이페이지 프로필, 제보 게임 상세 ‘제보자’ 줄. 마이페이지 ‘뱃지·칭호’에서 진행도·다음 목표·대표 칭호 고르기.
  - **첫 화면 계정 패널**(로그인 후 오른쪽 위): 찜·리뷰·제보 승인 수, 대표 칭호(자동이면 ‘자동’ 표시)와 보유 칭호 아이콘·개수, 다음 칭호까지 남은 조건(제보·리뷰 중 가까운 것 먼저, 진행 막대), 최근 획득한 업적 3개(알림을 확인한 순서 기준). 왼쪽 ‘게임 찾기’ 칸이 늘어나 패널과 아래 끝을 맞춤.
  - **새 칭호 알림**: 받은 뱃지 중 아직 알리지 않은 것을 `/api/auth/me` 의 `newBadges` 로 돌려주고, 화면 오른쪽 아래에 축하 카드(뱃지 그림·칭호·설명, ‘대표 칭호로 달기’/‘확인’)를 띄움. 확인하면 `users.badges_seen` 에 기록해 다시 알리지 않음. 리뷰를 지우거나 제보 게임이 내려져 뱃지를 **잃으면 기록에서 지워**, 다시 얻으면 다시 알림. 리뷰를 쓰거나 지울 때·마이페이지를 열 때·다른 탭에서 돌아올 때(30초에 한 번) 내 정보를 다시 받아 확인. 처음(기록 없음)에는 이미 가진 뱃지를 ‘본 것’으로 기록하고 알리지 않음.
  - API: `GET /api/me/badges`, `POST /api/me/badges/seen` (`{ids}`), `PUT /api/me/badges/selected` (`{id}` 또는 `{id:null}` 자동)
- **제보자**는 마이페이지 ‘내 제보’에서 상태(검토 중·승인됨·거절됨)와 거절 사유를 봅니다.
- API: `POST /api/submissions`, `GET /api/me/submissions`, `DELETE /api/me/submissions/:id`, `GET /api/admin/submissions?status=`, `POST /api/admin/submissions/:id/approve`, `POST /api/admin/submissions/:id/reject` (`{reason}`).

### 평균 플레이 시간 (RAWG)
- 게임 상세의 ‘서비스 상태’ 줄 대신 **평균 플레이 시간**을 표시합니다(서비스 종료 게임은 여전히 목록에서 숨기고 상세에 안내).
- 출처: [RAWG API](https://rawg.io/apidocs) `GET /api/games?search=…&key=…` 결과의 `playtime`(시간 단위). 값의 계산 방식은 문서에 없어 ‘약 N시간’ 참고값으로 표시
- 같은 게임 판단: IGDB 원제·영문 별칭 중 하나와 RAWG 이름이 같고(공백·기호·괄호·플랫폼 표기 무시), 두 출처 모두 출시 연도가 있으면 **1년 차이까지** 허용. 원제→별칭 순으로 최대 2번 검색, 결과 10개까지 확인. 아니면 ‘정보 없음’. 0시간도 ‘정보 없음’
- 비는 이유 진단: `npm run check:apis` 6번 항목에 게임별로 찾았는지·못 찾은 이유·RAWG 검색 결과를 기록
- 상세 화면에서만 조회(목록은 조회 안 함), 결과는 하루 동안 메모리에 저장
- 이용 조건: 무료 월 20,000건·비상업 프로젝트, **데이터를 쓰는 페이지에 RAWG 링크 표시**(상세 정보 표의 ‘출처: RAWG’ 링크)
- 키: `.env` 의 `RAWG_API_KEY` (없으면 ‘정보 없음’)
- **RAWG에 없으면 AI 추정으로 대신**: `npm run prefill:players` 가 추천 인원과 함께 **메인 스토리를 끝내는 데 걸리는 시간**(HowLongToBeat ‘Main Story’ 같은 기준)을 Gemini에게 물어 `server/data/party-size.json` 의 `hours` 로 저장합니다. 상세에서 RAWG 값이 없을 때만 ‘약 N시간 (메인 스토리 기준) **AI 추정**’으로 표시합니다. 엔딩이 없는 온라인 게임이나 AI가 모르는 게임은 null → ‘정보 없음’. 1~1000시간 정수만 인정.
  - RAWG 값(플레이어 평균 기록)과 AI 값(메인 스토리 완료 기준)은 뜻이 달라 출처·기준을 함께 표시합니다.
  - 예전에 추천 인원만 정리한 항목은 플레이 시간을 물으려고 다음 실행 때 다시 정리합니다.
  - **게임위는 화면에 보이는 게임만**: `--grac` 은 먼저 IGDB에 같은 이름(이름·별칭·한국어명)이 있는지 확인해(IGDB 호출, Gemini 사용량과 무관, 결과는 사이트와 같은 `.cache/grac-igdb-check.json`) **IGDB에 없는 게임만** Gemini에게 묻습니다. IGDB에 있는 게임은 IGDB 카드로 보이므로 정리할 필요가 없습니다. `--grac` 만 주면 IGDB 게임은 훑지 않고, 하루 호출 수를 아끼려고 100개씩 묻습니다. 하루 한도(429 `…PerDay…`)에 걸리면 바로 멈추고 안내합니다.
  - **서비스 상태(AI 판단, 확장)**: 게임위 게임은 `status`(`upcoming` 출시 예정 · `released` 출시 · `ended` 종료 · 모르면 null)를 묻고(오늘 날짜를 함께 줌), 온라인 서버가 필요한 IGDB 게임(MMO·배틀로얄·멀티 전용)은 `ended` 를 묻습니다. **종료**면 검색·나만의 게임 찾기·첫 화면·인기·랭킹 목록에서 숨기고, 게임위 **출시 예정**은 ‘신작·출시 예정 → 출시 예정’ 아래 **국내 출시 예정** 칸(최근 등급분류 순 60개)과 카드의 ‘출시 예정’ 표시로 보여 줍니다. 예전에 ‘종료’로 판단된 게임은 다시 묻지 않고, 나머지는 다음 실행 때 상태를 마저 묻습니다.
  - **게임위 게임의 서비스 종료 여부(AI 판단)**: 게임위 API에는 서비스 종료 정보가 없어(등급 취소만 있음, 이미 제외), `--grac` 로 정리할 때 Gemini에게 `ended`(확실히 종료면 true, 서비스 중이면 false, 모르면 null)도 묻습니다. **true인 게임만** 검색·나만의 게임 찾기에서 숨기고, 상세에는 ‘AI가 서비스 종료로 판단’ 안내를 띄웁니다. 모르는 게임은 숨기지 않습니다. IGDB 게임은 IGDB `game_status`(Offline 등)를 따릅니다. AI 판단이라 틀릴 수 있습니다.
  - **IGDB로 추천 인원이 정해진 게임은 플레이 시간만** 묻고(프롬프트에 `onlyHours`), AI 인원은 저장하지 않습니다. 예전에 저장된 AI 인원은 다음 실행 때 지웁니다(플레이 시간은 유지). RAWG에 플레이 시간이 있는지는 미리 알 수 없어(게임마다 RAWG 검색 필요, 무료 월 2만 건) AI에게 함께 묻고, 화면에서는 RAWG 값을 우선합니다.

### 게임위 전용 게임의 이미지 (App Store)
- **미리 받아 두기**: `npm run prefill:images` 가 화면에 게임위 카드로 보이는 **모바일 게임**(IGDB에 없는 것, AI가 ‘종료’로 판단한 게임 제외, 최신 등급분류 순)을 App Store 검색 API로 찾아, 앱 이름과 개발사가 모두 같을 때만 아이콘·App Store 링크를 `server/data/app-store.json` 에 저장합니다. 서버는 이 파일을 읽어 **검색·목록 카드와 상세**에 아이콘을 붙입니다(30초 안에 새 내용 반영). 못 찾은 게임도 ‘확인함’으로 기록해 다시 묻지 않고(`--retry` 로 다시), 3.5초에 한 번씩 묻고(분당 약 20번 제한), 중간에 끊어도 이어서 합니다. `--limit`, `--dry` 지원.
- **IGDB 게임 스크린샷**: 상세 조회 때 이미 받아 오는 IGDB 응답의 `screenshots`(없으면 `artworks`) 주소를 최대 6장 그대로 써서 상세 ‘스크린샷’ 칸에 보여 줍니다(출처 IGDB). 추가 호출·미리 받기 없음, 갤러리는 중간 크기(`t_screenshot_med`)를 화면에 보일 때만 불러오고 누르면 큰 그림.
- **스크린샷도 사용**: App Store 검색 결과의 스크린샷(아이폰·아이패드, 애플 이미지 서버 주소만, 최대 6장)도 저장합니다. 카드 표지(세로)는 세로 스크린샷 → 첫 스크린샷 → 아이콘 순, 상세 배너는 가로 스크린샷, 상세 표지 칸은 아이콘(둥근 모서리, 잘리지 않게), 상세에 ‘스크린샷’ 갤러리(출처 App Store). 예전에 아이콘만 받아 둔 게임은 다음 실행 때 스크린샷을 받으러 다시 확인합니다.
- 파일에 없는(확인한 적 없는) 게임만 상세를 열 때 그 자리에서 찾아봅니다(아래 방식).
- IGDB에 없어 게임위 정보로 보여 주는 게임(주로 국내 모바일 게임)은 **상세 화면을 열 때** [App Store 검색 API](https://performance-partners.apple.com/resources/documentation/itunes-store-web-service-search-api/)(애플 공식, 키 없음)로 같은 앱을 찾아 **아이콘 이미지와 App Store 링크**를 보완합니다.
- 같은 앱 판단: 앱 이름(공백·괄호·플랫폼 표기 무시)이 게임물명과 같고, **개발사(sellerName/artistName)가 게임위 신청사와 같을 때만**((주)·주식회사·Co., Ltd. 등 무시). 하나라도 다르면 붙이지 않음
- 이미지·링크는 애플 주소(`mzstatic.com`, `apps.apple.com`)일 때만 사용
- 호출 제한(분당 약 20건)에 맞춰 분당 15건으로 자체 제한, 결과는 하루 저장
- 이용 조건(앱 홍보 용도, ‘App Store에서 다운로드’ 표시 옆 사용)에 맞춰 아이콘 바로 아래에 다운로드 링크와 ‘이미지: App Store’ 표시
- 한계: 안드로이드 전용 게임(Google Play는 공식 검색 API 없음)·아케이드·크레인 게임은 이미지 없음 유지. 끄려면 `.env` 의 `APPSTORE_LOOKUP=false`
- 확인: `npm run check:apis` 7번 항목

### 글로벌 평점 vs 회원 평점
- **글로벌 평점**: IGDB `total_rating`(IGDB 이용자 평점 `rating` 과 평론가 평점 `aggregated_rating` 의 평균, 100점 만점)을 **÷20 해서 5점 만점**(소수 첫째 자리)으로 표시. 평가 수 `total_rating_count` 와 이용자/평론가 내역도 함께 표시
- **플레이픽 회원 평점**: 회원들이 남긴 별점(1~5)의 평균
- 카드: ‘글로벌 ★4.2 · 회원 ★4.7 (3)’, 상세: 두 평점을 나란히 보여 주고 차이를 문장으로 안내(차이 0.25점 미만은 ‘비슷해요’)
- IGDB에 평가가 없거나 IGDB에 없는 게임(게임위 전용·데모)은 글로벌 평점을 만들지 않고 ‘없음’으로 안내

### 게임 소개 번역 (DeepL)
- IGDB 소개는 대부분 영어라 **DeepL API**로 한국어로 번역해 보여 줍니다(`server/services/translator.js`).
  문서: https://developers.deepl.com/docs/api-reference/translate — `POST /v2/translate`, 헤더 `Authorization: DeepL-Auth-Key <키>`, `{ text: [...], target_lang: "KO" }`
- 번역 대상: 게임 상세 페이지 소개 + 첫 화면 캐러셀 5개(목록 카드에는 소개를 표시하지 않아 사용량 절약)
- 번역 결과는 `.cache/translations.json` 에 저장해 같은 문장을 다시 번역하지 않습니다.
- 키가 없거나 실패(한도 초과 등)하면 **번역한 척하지 않고 원문을 그대로** 보여 주며 ‘번역 정보가 없어 원문을 표시합니다’라고 안내합니다.
- 키: `.env` 의 `DEEPL_API_KEY` (DeepL API Free 키는 `:fx` 로 끝나며 자동으로 무료 엔드포인트 사용)

## 2. 추천 기준과 필터 동작

조건마다 게임 데이터와 비교해 세 가지로 판정합니다.

| 조건 | 일치(✓) | 불일치(✕) | 정보 없음(?) |
|---|---|---|---|
| 인원수 N | **추천 인원** 최소 ≤ N ≤ 최대 (‘5명 이상’은 추천 최대 ≥ 5). 추천 인원이 없는 게임(게임위·데모)은 최대 인원 범위 | 범위 밖 | 인원 정보가 없음(AI도 모른다고 한 경우 포함) |
| 플랫폼 (복수 선택) | 선택한 플랫폼 중 **하나라도** 지원 | 하나도 지원 안 함 | 플랫폼 정보 없음/분류 불가 |
| 장르 (복수 선택) | 선택한 장르 중 **하나라도** 해당 | 하나도 해당 안 함 | 장르 정보 없음/분류 불가 |

- 선택하지 않은 조건(예: 인원 ‘상관없음’)은 판정에서 제외됩니다.
- **모든 조건 일치**: 선택한 모든 조건이 ✓ → 상단 구역.
- **일부 조건 일치**: 1개 이상 ✓이고 나머지가 ✕ 또는 ? → 하단 구역. 카드 배지로 어떤 조건이 일치했는지 표시.
- 일치하는 조건이 **하나도 없는 게임은 제외**합니다. 남는 게임이 없으면 ‘결과 없음’ 화면.
- 정렬: 일치 조건 수 많은 순 → 불일치 수 적은 순(정보 없음은 불일치보다 앞) → 제목 가나다순.
- 정보가 없는 값은 추측하지 않고 **‘정보 없음’** 으로 표시하며, 매칭에서도 ‘일치’로 치지 않습니다.

구현: `server/services/recommend.js`, 선택지와 문자열 매핑: `server/services/taxonomy.js`

## 5. 데이터와 실제 API 연동

### 데모 데이터 (`server/data/demoGames.js`)
- **실존하지 않는 가상 게임 16개**입니다. 이름·업체·설명 모두 시연용입니다.
- 이미지는 넣지 않았고, 구매처는 앱 내부 ‘데모 구매처’ 안내 페이지로만 연결됩니다.
- ‘정보 없음’ 표시를 확인할 수 있도록 일부 게임은 인원·플랫폼·장르·구매처를 비워 두었습니다.
- 화면 상단의 **데모 모드 배너**와 카드의 **‘데모’ 표시**로 구분됩니다.

### ① 게임물관리위원회 게임 검색 Open API (IGDB에 없는 게임 추가·국내 등급 보완)
기준 문서: [게임위 Open API 가이드](https://www.grac.or.kr/OpenBook/OpenAPIGuide.aspx) (공공데이터포털 [15120667](https://www.data.go.kr/data/15120667/openapi.do)은 이 가이드로 연결되는 LINK형)

- 요청 주소: `https://www.grac.or.kr/WebService/GameSearchSvc.asmx/game`
  (가이드의 실제 호출 예 `.../game?display=10&pageno=1` 을 따라, `op=game` 은 주소의 `/game` 경로로 지정)
- 요청 변수: `display`(필수, 최대 1000), `pageno`(필수), `gametitle`, `entname`, `rateno`, `startdate`, `enddate`(yyyy-mm-dd)
- 응답(XML): `result` > `tcount`, `pageno`, `res_date`, `item[]`
  (`rateno`, `rateddate`, `gametitle`, `orgname`, `entname`, `summary`, `givenrate`, `genre`, `platform`, `descriptors`, `cancelstatus`, `canceledddate`)
- 오류: `<error><message/><error_code/></error>` → 화면에 오류 코드·메시지 표시
- **인증키: 가이드에 인증 변수가 없어 키 없이 호출합니다.**
- **호출 제한: 가이드에 명시 없음** → 응답 캐시(`GRAC_CACHE_TTL`, 기본 1시간)와 페이지 수 제한(`GRAC_MAX_PAGES`, 기본 1)으로 호출 최소화

장르·플랫폼 매핑 (`server/services/taxonomy.js`, 가이드에 적힌 값과 **정확히 일치할 때만**)

이 API에 없는 정보: **플레이 인원수, 구매처 링크, 이미지.** → live 모드에서 인원 조건은 항상 ‘정보 없음’이라
인원을 선택하면 ‘모든 조건 일치’가 나오지 않고 ‘일부 조건 일치’로 표시됩니다. 국내 게임 DB API 등 별도 출처가 필요합니다.

동작 방식(`gracProvider.js`): API에 장르·플랫폼 검색 변수가 없으므로, 설정한 기간·페이지 수만큼 목록을 받아 캐시한 뒤
서버에서 조건 매칭합니다. 원페이저의 ‘국내 이용 가능 게임’ 기준에 따라 **등급거부(등급분류번호 없음)·등급취소 항목은 제외**합니다.

검증 상태: 사용자 PC에서 `npm run check:apis` 로 실제 호출 확인(2026-10-29). 키 없이 HTTP 200, 정상 XML(가이드 샘플의 오타 없음), 장르·플랫폼 값이 가이드 목록과 일치.
주의: 목록은 최신 등급분류 순으로 오며 최근 항목은 대부분 소규모 모바일·아케이드 게임입니다. 기본 설정(1,000건)으로는 IGDB 인기 게임과 겹치는 경우가 드뭅니다.

### ② IGDB (기본 데이터 출처)
- 인증: Twitch Client credentials — `POST https://id.twitch.tv/oauth2/token` (client_id, client_secret, grant_type=client_credentials) → `access_token`, `expires_in`. 서버에서만 발급·캐시(만료 60초 전 갱신, 401 시 1회 재발급)
- 호출: `POST https://api.igdb.com/v4/{games|genres|platforms}` 헤더 `Client-ID`, `Authorization: Bearer <토큰>`, 본문은 Apicalypse 쿼리
- 필드: [공식 스키마 igdbapi.proto](https://api.igdb.com/v4/igdbapi.proto) 기준 — `multiplayer_modes`, `game_modes`, `genres`, `platforms`, `cover.url`, `websites.url`, `game_localizations`, `alternative_names`, `age_ratings.organization`, `age_ratings.rating_category`, `game_status.status`, `game_type.type`, `parent_game`, `total_rating(_count)`, `rating(_count)`, `aggregated_rating(_count)`
- 공식 문서 사이트(api-docs.igdb.com)는 개발 환경에서 열리지 않아, 헤더·쿼리 문법과 장르·플랫폼·등급 값은 `npm run check:apis` 로 실제 응답과 대조해야 합니다.
- 키: `.env` 의 `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET` (없으면 경고와 함께 게임위 데이터만 사용)

동작 (IGDB 기준 + 게임위 보완)
1. **추천 목록 = IGDB 게임 + IGDB에 없는 게임위 게임을 한 목록으로** 보여 줍니다. IGDB가 없거나 실패하면 게임위 목록으로 대신 보여 줍니다(경고 표시).
   - **모든 조건 일치 = IGDB 전체 검색**: 조건을 IGDB 쿼리의 `where` 로 보내 전체 DB에서 찾고, 인기순(`total_rating_count`)으로 24개씩 받아 옵니다(‘더 보기’ = 다음 페이지 `offset`). 개수는 `/games/count` 로 셉니다.
     - 장르 `genres = (…)`, 플랫폼 `platforms = (…)` (여러 개 고르면 하나라도 해당)
     - 인원 1명 `game_modes = (1)`(싱글 플레이), n명 `multiplayer_modes.onlinemax/offlinemax/onlinecoopmax/offlinecoopmax` 중 하나라도 ≥ n (5 = 5명 이상)
     - 받아 온 게임도 화면 판정 규칙(아래)으로 다시 확인해 정말 모두 일치하는 것만 보여 주므로, 표시 개수는 ‘약 N개’입니다.
   - **일부 조건 일치 = 인기 후보에서 판정**: 일부 일치는 IGDB 쿼리로 표현하기 어려워, 선택한 장르·플랫폼의 인기 게임 최대 300개(+2명 이상이면 멀티 인원 정보가 있는 게임 200개)에서 찾습니다.
   - 전체 검색 쿼리가 실패하면 기존 방식(인기 후보 안에서만 판정)으로 대신하고 경고를 띄웁니다. `npm run check:apis` 의 ‘3-1’ 항목에서 실제 IGDB 응답으로 확인할 수 있습니다.
   - **IGDB에 없는 국내 등급분류 게임**: 게임위 API에는 장르·플랫폼 조건 검색이 없어, 서버가 켜질 때 게임위 전체 목록(약 3만 건)을 1000건씩 받아 `.cache/grac-index.json` 에 저장합니다(처음 한 번 몇 분, 이후 하루 한 번 새 등급분류분만 추가, 7일마다 전체 다시 받아 등급 취소 반영. `GRAC_INDEX=off` 로 끔).
     - 선택한 **플랫폼·장르가 게임위 자료로 모두 ‘일치’**인 게임만 (인원은 AI 추정, 장르가 ‘크레인’처럼 분류에 없는 값이면 제외). 인원만 고르면 찾지 않습니다.
     - 최신 등급분류 순으로 (12개씩 3묶음을 동시에) 훑으며 IGDB에 **같은 이름(이름·별칭·현지화명, 대소문자 무시 정확 일치, 괄호·플랫폼 표기 뗀 기본 제목 포함)**이 있는 게임은 뺍니다. 확인 결과는 `.cache/grac-igdb-check.json` 에 30일 저장.
     - **합치는 위치**: AI 추천 인원을 붙여 판정한 뒤, **모든 조건이 일치하면 ‘모든 조건 일치’**에 IGDB 게임 4개마다 1개씩 섞고(인기 순위가 없어 비율로 섞음, IGDB 결과가 끝나면 게임위 게임만 이어서), **아니면(AI도 인원을 모르는 경우 등) ‘일부 조건 일치’**에 같은 정렬 규칙(일치 수 → 불일치 수 → 국내 등급 → 제목)으로 합칩니다. 인원을 안 골랐으면 게임위 게임은 ‘모든 조건 일치’의 ‘더 보기’와 함께, 골랐으면 ‘일부 조건 일치’의 ‘더 보기’와 함께 불러옵니다. ‘더 보기’는 섹션별로 서버에서 이어 받습니다(`offset`=IGDB 위치, `goffset`=게임위 위치).
     - 전체 목록을 준비하는 동안에는 결과 위에 ‘준비 중’ 안내가 나오고 IGDB 게임만 보입니다. `npm run check:apis` 의 ‘8’ 항목에서 실제 응답 시간과 IGDB 확인을 볼 수 있습니다.
   **검색**은 IGDB 결과 중 **검색어와 이름이 실제로 맞는 게임**(원제·한국어명·별칭에 검색어 포함)이 있으면 IGDB 게임만 보여 줍니다(같은 게임이 두 번 나오는 것 방지). IGDB 결과가 없거나 이름만 비슷한 엉뚱한 게임뿐이면 게임위 결과를 먼저 보여 줍니다(예: IGDB에 한국어 이름이 없는 ‘로스트아크’).
   **정렬과 게임위 결과**: 이름이 검색어와 같은 게임 → 검색어로 시작하는 게임(이름이 짧은 본편 먼저) → 검색어를 포함하는 게임 → 그 밖 순서. IGDB에 이름이 맞는 게임이 있어도, IGDB와 합쳐지지 않았고 이름에 검색어가 들어간 게임위 게임은 함께 보여 줍니다(예: ‘메이플’ → IGDB에는 한국어 이름이 있는 속편만 걸려도 게임위 ‘메이플스토리’ 본편이 맨 앞). 게임위 제목 검색은 100건까지 받습니다.
   **한글·영문 어느 쪽으로 검색해도 같은 결과**: DeepL 키가 있으면 검색어를 한↔영으로 번역해 함께 찾습니다(IGDB는 원래+영문 검색어, 게임위는 원래+한글 검색어). 게임위의 한글 제목도 영문으로 번역해 IGDB 게임과 같은 게임인지 확인하고(번역은 틀릴 수 있어 **플랫폼이 겹칠 때만**), 같으면 IGDB 카드 하나로 합쳐 한글 이름·국내 등급을 붙입니다. 번역 결과는 `.cache/translations.json` 에 저장(같은 제목은 다시 번역 안 함). 결과 위에 ‘○○(으)로도 함께 찾았어요’ 표시. 키가 없으면 원래 검색어만 사용.
   **띄어쓰기 없이 입력해도 찾기**: IGDB 검색은 띄어쓰기를 구분해 `lostark` 로는 ‘Lost Ark’ 가 안 나옵니다. 영문·숫자 4~24자 검색어는 띄어 쓴 경우들을 IGDB slug(`lost-ark`, `league-of-legends` 처럼, 20자 이하는 두 군데까지)로 만들어 **정확히 같은 이름**의 게임을 한 번의 추가 조회로 함께 찾습니다.
   검색이 이상할 때: `npm run check:search -- 검색어` → IGDB·게임위 결과와 최종 결과를 `search-check.log` 로 저장
2. **같은 게임 판단 (중복 제거)**: 게임위 제목, 또는 괄호·대괄호와 끝의 플랫폼 표기(‘(PS4)’, ‘for Nintendo Switch’, ‘- 모바일’ 등)를 뗀 기본 제목이
   IGDB 이름·한국어 현지화명·별칭 중 하나와 (공백·기호 제외) 같으면 같은 게임으로 보고 **카드는 IGDB 하나만** 보여 줍니다.
   - 게임위 항목 중 **플랫폼이 겹치는 것**이 있으면(여러 개면 최신 등급분류) 그 항목의 **국내 등급분류 정보와 한글 제목**만 보완합니다.
   - 플랫폼이 겹치는 항목이 없으면 같은 이름의 다른 판일 수 있어 등급은 붙이지 않습니다(카드도 추가하지 않음).
3. **IGDB에 없는 게임위 게임만** 별도 카드로 추가하며, 같은 제목(플랫폼별·재심의 항목)은 **하나로 합칩니다**(최신 등급분류 기준, 플랫폼·장르는 합집합).
   IGDB 목록·검색은 **본편만** 보여 줍니다: 다른 판(에디션·이식판, `version_parent`)과 본편에 딸린 항목(시즌·DLC·확장팩·에피소드, `parent_game`)을 쿼리에서 빼고, `game_type` 이 DLC·번들·팩·업데이트·모드·시즌·에피소드·확장팩인 항목도 한 번 더 거릅니다(예: ‘오버워치’ 검색 시 ‘Season 2·3…’ 제외). 독립 확장판·리메이크·리마스터는 별도 게임으로 둡니다. 이름이 같은 다른 게임은 카드에 출시 연도를 함께 표시해 구분합니다.
4. 국내 등급: 게임위 등급 → 없으면 IGDB의 한국(GRAC) 등급 → 둘 다 없으면 **‘국내 등급 정보 없음’**. 같은 일치 수라면 국내 등급이 확인된 게임이 먼저 나옵니다.
5. 상세 페이지(IGDB 게임)는 게임위 API를 제목(`gametitle`)으로 검색해 정확히 같은 게임이 있으면 국내 등급을 보완합니다.
6. 한쪽 API가 실패하면 나머지 결과와 함께 경고 문구를 보여 주고, 둘 다 실패하면 오류 화면을 보여 줍니다.
7. **서비스 종료 게임 숨김**: IGDB `game_status.status` 가 `Offline`(서비스 종료)인 게임은 첫 화면·추천·검색 목록에서 빼고,
   같은 제목의 게임위 항목도 따로 나오지 않게 합니다. 상세 주소로 직접 들어가면 ‘서비스 종료’ 안내와 함께 보여 줍니다.
   숨길 상태는 `.env` 의 `IGDB_HIDE_STATUSES`(예: `Offline,Delisted,Cancelled`)로 바꿀 수 있습니다.
   한계: IGDB에 상태가 입력되지 않은 게임은 걸러지지 않으며, 게임위 데이터에는 서비스 종료 정보가 없습니다.

IGDB 값 → 플레이픽 값
- **최대 인원**: `multiplayer_modes` 의 online/offline/coop 최대 인원 중 최댓값 = 최대 인원, 최소 인원은 `game_modes` 에 Single player가 있으면 1 아니면 2. 멀티플레이 정보 없이 Single player만 있으면 1명. 그 외는 정보 없음.
- **추천 인원** (친구들과 한 팀으로 같이 하는 인원. 예: 배그는 최대 100명이지만 추천 1~4명) — `recommendFromIgdb` + `services/partySize.js`
  1. IGDB **협동 최대 인원**(`onlinecoopmax`/`offlinecoopmax`)이 2명 이상 → 그 값 (출처 ‘IGDB 협동 플레이 인원’)
  2. 최대 인원이 8명 이하(싱글 전용 포함) → 최대 인원 그대로 (출처 ‘IGDB’)
  3. 그 밖(대규모 대전·MMO처럼 최대 인원만 크거나 정보 없음) + **게임물관리위원회에만 있는 게임**(인원 정보 자체가 없음) → **Google Gemini에게 추정**을 요청 (`GEMINI_API_KEY`, 기본 모델 `gemini-flash-lite-latest` — `npm run check:gemini` 점검에서 게임 3개 1~2초, 생각 토큰 0. 일반 Flash는 무료 사용량이 금방 차서(429) 제외). IGDB 게임은 원제·출시 연도·플레이 모드·IGDB 최대 인원, 게임위 게임은 한글 제목·업체·플랫폼·장르·등급분류 연도를 주고 ‘같이 하는 그룹 인원’을 JSON으로 받습니다. 모르는 게임은 null로 답하게 해서 **‘정보 없음’**으로 둡니다(한글 제목만으로 어떤 게임인지 모르면 장르만 보고 짐작하지 말라고 지시). 게임위 게임은 기본 제목(괄호·플랫폼 표기 뗀 것) 단위로 한 번만 묻습니다.
     - 검증: 정수, 1 ≤ 최소 ≤ 최대 ≤ 32, IGDB 최대 인원을 넘지 않게 자름. 결과는 아래 데이터 파일에 저장.
     - 화면: 상세의 ‘추천 인원’ 옆에 **‘AI 추정’** 표시(실제 데이터가 아님을 안내), 카드에는 ‘1~4명 (AI)’. 최대 인원이 다르면 ‘최대 인원’ 줄을 따로 보여 줍니다.
     - **미리 정리해 두고 읽기만**: 검색할 때 AI를 부르지 않습니다. `npm run prefill:players` 가 IGDB 인기 게임(평가 수 순, 기본 3000개 훑기)과 선택 시 게임위 게임(`--grac 2000`, 최신 등급분류 순, IGDB에 있다고 확인된 것 제외) 중 **AI 대상만** 골라 50개씩 묶어 묻고 `server/data/party-size.json` 에 저장합니다.
       - 저장 형식(태그): `{ "27789": { "min": 1, "max": 4, "model": "gemini-3.5-flash-lite", "date": "2026-10-29" } }`, AI도 모르면 `{ "unknown": true, ... }`. 키는 IGDB 게임 번호 또는 `grac:기본제목`.
       - 속도: 묶음 여러 개를 **동시에**(`--parallel`, 기본 3) 보내되 **분당 호출 수**(`--rpm`, 기본 15) 안에서. 한도를 넘어 429가 나면 모두 1분 쉬고, 계속 걸리면 멈춤. 무료 한도가 넉넉하면 `--rpm 30` 등으로 올리면 빨라집니다.
       - 이미 정리된 게임은 건너뛰어 **중간에 끊어도 다시 실행하면 이어서** 합니다. 무료 한도(429)면 1분씩 3번 기다려 보고 멈춤. `--dry` 로 개수·예상 시간만 확인.
       - 서버는 이 파일만 읽고(서버가 켜져 있어도 30초 안에 새 내용 반영), **정리 안 된 게임은 ‘정보 없음’**. 파일은 git 에 올려 팀원과 같이 쓸 수 있습니다(키 불필요).
       - `AI_PLAYERS_LIVE=on` 이면 예전처럼 파일에 없는 게임을 검색 때 바로 묻습니다(12개씩 4개 동시, 최대 8초 대기, 429면 10분 쉼). 기본은 끔.
     - 데이터 파일도 키도 없으면 AI 없이 3)의 게임은 IGDB 최대 인원을 그대로 씁니다(이전 방식).
  - ‘나만의 게임 찾기’의 인원 판정도 추천 인원 기준입니다. IGDB 쿼리는 최대 인원으로 넓게 거른 뒤(추천 ≤ 최대이므로 빠지는 게임 없음) 추천 인원으로 다시 판정하고, 줄어드는 만큼 한 번에 48개씩(일치가 12개 미만이면 한 번 더) 훑습니다. `npm run check:apis` 9번 항목에서 실제 값을 확인할 수 있습니다.
- **구매처**: `websites` URL 중 Steam·Epic·GOG·itch.io·App Store·Google Play·PlayStation Store·Xbox/Microsoft Store·Nintendo eShop 주소만 인정.
- **표지**: `cover.url` (IGDB 이미지 서버).
- **제목**: 한국어 현지화명이 있으면 한국어, 없으면 IGDB 원제. 소개는 IGDB 원문(대부분 영어).
- 장르·플랫폼 이름 매핑: `server/providers/igdbProvider.js` 의 `IGDB_GENRE_NAMES`, `IGDB_PLATFORM_NAMES`.

### ③ 국내 게임 DB API — **서비스 확정 필요**
원페이저·대본에 ‘국내 게임 DB API’라고만 되어 있어 어떤 서비스인지 정할 수 없습니다.
`krGameDbProvider.js` 에 자리(인원수·구매처·이미지 보강용 `enrich()`)만 만들어 두었고, 키를 넣어도 구현 전에는 연결된 척하지 않고 `NOT_IMPLEMENTED` 오류를 반환합니다.

### 실제 API(IGDB + 게임위)로 전환하는 방법
1. `.env` 에서 `DATA_SOURCE=live` 로 변경하고 `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET` 입력 (게임위 API는 키 불필요)
2. 필요하면 조회 범위 조정: `GRAC_START_DATE`, `GRAC_END_DATE`, `GRAC_MAX_PAGES`
3. `npm start` → http://localhost:4000 에서 검색. 상단 ‘데모 모드’ 배너가 사라지고 출처가 ‘IGDB, 게임물관리위원회’로 표시됩니다.
   호출이 실패하면 데모로 대체하지 않고 오류 화면이 나옵니다.
4. 빠른 확인: `curl "http://localhost:4000/api/recommendations?platforms=pc&genres=rpg"`
